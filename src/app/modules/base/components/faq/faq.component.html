ChatDRex — Frequently Asked Questions

What is ChatDRex?

ChatDRex is a conversational, no‑code, multi‑agent system for network‑based disease‑module identification and drug repurposing. It provides natural‑language access to the integrated systems medicine knowledge graph NeDRex and orchestrates specialized bioinformatics agents for analysis and in‑silico validation.

The approach is described in: “Conversational no-code and multi-agentic disease module identification and drug repurposing prediction with ChatDRex ” by Simon Süwer, Kester Bagemihl, Sylvie Baier, Lucia Dicunta, Markus List, Jan Baumbach, Andreas Maier, and Fernando M. Delgado‑Chaves (shared first/last authors).

Who is ChatDRex for? Do I need coding skills?

ChatDRex is designed for clinicians and researchers who want to run complex bioinformatics workflows without programming. You ask questions in plain language; the system plans the analysis, calls the right tools, and returns interpretable results with links and visualizations.

Which analyses can ChatDRex run end‑to‑end?

A typical workflow combines:

  • Schema‑constrained KG querying over NeDRex (Cypher/Neo4j).
  • Disease‑module expansion with DIAMOnD (seed‑gene driven).
  • Drug prioritization via TrustRank or Closeness Centrality.
  • In‑silico validation with DIGEST (functional coherence from GO/KEGG).
  • Literature grounding with a Research agent (Semantic Scholar).
  • Interactive visualization using Drugst.One with a consistent legend.
 How does the multi‑agent system work?

A central Planning agent decomposes your request and routes subtasks to expert agents (KG, Network, DIGEST, Research, Visualization, Finalize). Each agent uses few‑shot prompts, short/long‑term memory, and tool calling. Results are merged into a coherent answer with figures and citations.

How are hallucinations and errors mitigated?

ChatDRex employs input guardrails (prompt‑injection checks), schema‑constrained Cypher generation with deterministic templates and embedding‑assisted ID matching, and a Finalize step with paragraph‑level verification. If Cypher generation fails repeatedly, a GraphRAG fallback retrieves graph‑guided context to maintain accuracy.

Which data sources and tools are integrated?

Core components include NeDRexDB/NeDRexAPI (KG access and network tools), DIAMOnD (disease‑module detection), TrustRank and Closeness Centrality (drug ranking), DIGEST (functional coherence), Semantic Scholar (literature), and Drugst.One (graph visualization).

What models does ChatDRex run on? Can I change them?

By default we use gpt‑oss‑20b, hosted via Ollama behind a self‑hosted OpenWebUI. The multi‑agent design is modular—administrators can swap or upgrade models per agent as better LLMs become available.

Do I need to install anything? Is there a web UI?

You can use the hosted web interface: apps.cosy.bio/chatdrex. For local deployments, the Angular front end connects to Quarkus backends via WebSocket; the backend also offers REST and an MCP server for tool integration.

Where is the code? What’s the license?

Source code: ChatDRexAPI4J and ChatDrexUI. The software is free for academic and non‑profit use under the BSD 3‑Clause License. Commercial users: please contact the CoSy.Bio Lab (University of Hamburg) for a license.

How should I cite ChatDRex?

Please cite the paper “Conversational no‑code multi‑agentic disease module identification and drug repurposing with ChatDRex” (Süwer et al., 2025). Include the version used and date accessed, plus related tool references where appropriate.

What are current limitations?

Results depend on input quality and database coverage; some outputs require expert interpretation. LLMs can still produce plausible but irrelevant content, so guardrails and literature checks are used. Ongoing maintenance is needed as databases and tools evolve.
